## Modifications

`seed/` and `current/` are byte-for-byte as the API returned them, each pinned to the `revid`
and `sha256` recorded in `manifest.json` — **with one deliberate exception, recorded here
because CC BY-SA asks that changes be indicated and because the hash guard cannot tell you.**

**`seed/Deadpool_Wolverine.wikitext` carries two planted errors (Sept 3, 2026).** The lead and
the first cast entry were changed to name Tom Holland rather than Ryan Reynolds as Wade
Wilson/Deadpool, and a sentence saying Reynolds does not appear was added. Both are false, and
deliberately so: they are the test fixture for whether the agent detects a defect introduced
into a page it monitors. The manifest's `sha256` for that file was re-pinned to the edited
bytes, so every integrity check in the repo passes — which is exactly why this paragraph
exists. Revision 2019481 as MCU Wiki contributors actually wrote it does **not** contain these
lines, and the wiki's own history is the authority. To restore the file:
`git log --follow -p snapshots/seed/Deadpool_Wolverine.wikitext`, or re-pull it with
`python3 scripts/pull_snapshots.py`.

Everything else under `seed/` and `current/` is untouched. The authorship recorded in
`manifest.json` stands: this is the wiki contributors' work, two altered lines
notwithstanding.

**The wiki's table file is unmodified text in a different container.** It is generated by
`scripts/build_wiki_db.py`, which re-lays the `seed/` files as MediaWiki-shaped `page` /
`revision` / `text` rows so the simulated wiki has a database-shaped store to read
(`AGENTS.md` §2). Every `old_text` value is the byte-identical content of the corresponding
`seed/` file, and the builder re-checks each one against the manifest's `sha256` as it reads
it, so a drifted corpus fails the build rather than becoming the seed.

**It is committed twice, byte for byte, and the duplication is forced.** `FE/` is served as a
static directory, so the browser can only fetch what sits under it — the copy at
`FE/data/wiki-db.json` is the one the wiki actually loads, and `snapshots/wiki-db.dummy.json`
is the canonical one beside the corpus it derives from. The builder writes both in the same
pass so they cannot drift.

The layout is ours and is MIT; the text inside both copies is not, and carries CC BY-SA 3.0
exactly as the `.wikitext` files do. Edits the agent makes to the loaded copy live only in the
browser and are redistributed by nobody — but they are derivative works, and share-alike would
carry onto them if they were.

Text this project *generates* — the agent's drafted section edits, and the seeded MediaWiki
instance built from `seed/` — **is** a modification of CC BY-SA 3.0 material. It therefore
carries the same licence, and any deployed instance must credit the MCU Wiki and link the
licence on the page. Share-alike is inherited, not optional.

## What is MIT

Everything else: `backend/`, `tests/`, `scripts/`, and the project documentation. The code that
reads and rewrites the text is ours; the text is not.

## Reproducing

```bash
python3 scripts/pull_snapshots.py
```

`seed/` is pinned to historical revision ids and must come back byte-identical indefinitely
(verified). `current/` tracks the live wiki and is expected to change whenever editors touch
a page — that drift is the point, not a defect.
